Inspect source and verify your deployment.

Local checks exercise program invariants, signed transaction validation, durable payment state, refusal under uncertainty and the browser interface. Synthetic fixtures are not live receipts.

Reproduce the checks

Build the program from locked source dependencies, run Rust and integration tests, and run the local browser fixtures. Follow the public setup instructions for commands and prerequisites.

Limits

No live deployment, current service availability, live-wallet acceptance or independent human acceptance is claimed. Live deployment and financial operations are NOT RUN by these presentation fixtures. Test tokens have no monetary value. An unknown outcome retains its original payment identity and blocks unsafe retries.

Privacy and deployment review

A successful scanner alone does not certify privacy or security. Deployment acceptance must independently verify the network, program, executable bytes, upgrade authority and trusted operational data.

Server-independent recovery

The payer-direct tools need trusted RPC and an independently pinned deployment; browser recovery still uses application routes. See the recovery prerequisites and limits.
