# Deployment templates

These templates support the facilitator, protected resource, payment lab and bounded operator tools. They do not select an accepted installation, install a controller, start services or submit transactions by being present in this repository. Never place deployed credentials, original signed wires, operational journals or owner approvals in source control.

An authorized installer provides `/etc/capture402/operational-data.json` (`schema: 1`) and the accepted record at `/etc/capture402/deployment-identity.v1.json`. The runtime reads the operational policy through a fixed path, checks root ownership and non-writable ancestry, refuses links and concurrent metadata changes, and obtains `deploymentRecordSha256` only from that trusted file. A record cannot choose its own acceptance hash; environment/request parameters cannot select another trust-policy path. The full record schema and live finalized loader/executable comparison remain mandatory. Missing installation policy fails closed. Synthetic test records never become runtime acceptance defaults.

The trusted policy contains installation-specific identities and reviewed dispositions. Relevant optional feature groups include `merchantDemoPolicy`, `b3RecoveryPolicy`/`b3RecoverySourceSha`, `authorizeAbandonPolicies`, `authorizeIsolationPolicy`, `acceptedExecutableSha256`/`acceptedExecutableSizeBytes`, `admissionContracts`, `e2eApplicationRelease`, `preSignerStop`, `acceptedExternalFunding`, `sponsorAddress`, `merchantAddress`, `mintAddress`, `browserAddress`, `campaignReference`, `publicOrigin`, `devOrigin` and `e2eOrigin`. A selected feature refuses missing or inconsistent fields; no example wallet, funding signature, source revision or permissive fallback is shipped. The repository's tests use explicitly synthetic policy fixtures and test-only mocks.

Supply RPC configuration through `SOLANA_RPC_URL` using the separately approved HTTPS Helius or QuickNode endpoint. Keep its credentials private. Operator preparation checks the pinned network before use; funding or payment uncertainty retains the original request/signature/wire and stops further execution. Never switch providers or resend an uncertain operation. Devnet funding uses the explicitly configured QuickNode `requestAirdrop` API under separate owner authority.

The `*.env.example` files describe separate role configuration. Keep the facilitator sponsor key distinct from merchant, payer and mint roles. Bearer and merchant access credentials are separate. Template host values must be rendered from the trusted installation configuration. Use loopback listeners and the matching nginx route fragments; preserve existing TLS, exact route/method allowlists, rate limits and the separation of static presentation from economic routes. `/integrate`, `/evidence` and `/assets/guide.css` are GET-only. Order-session restoration is an access-only original-payer message and grants no merchant authority.

Build the SBF from approved source before deterministic tests. Build the wallet bundle from pinned dependencies and retain its linked legal notices. Compare the exact source, binary, configuration, process and routes during separately authorized installation acceptance. Source tests and a local build do not certify a deployed service.

The lab keeps immutable original terms and original action identifiers. Merchant captures occur before the stored capture deadline; payer reclaim opens at that deadline and needs a payer signature and native network fees. Expiry transfers nothing. Merchant-funded refund is separate and requires merchant liquidity and its refund window. The opt-in paid report withholds both artifacts until all exact original settlement proofs and durable completed response exist. Incomplete runs retain their execution locks across restart.

UNKNOWN operations retain original wires, signatures, journals, locks and reservations. Diagnostics and completed-response retrieval do not replay economics. The UNKNOWN-CAPTURE recovery CLI continues to refuse live use without a trusted enrollment verifier; multi-UID live recovery is unsupported. A separately installed trusted policy does not by itself authorize activating recovery, deployment or payments.

Generic controllers, release checks and operator source are developed in the public repository. Installation values, historical evidence and runtime state remain private data. Changing source-of-truth or controller policy requires exact-source review and separate owner authorization; merge and deployment are distinct actions.

## Operational data reference

`operational-data.schema.json` documents field shapes. `operational-data.example.json` is deliberately incomplete: the new repository has no assigned ID and no accepted installation. Null fields fail schema/runtime checks. Do not install it, replace nulls with invented IDs, copy synthetic test fixtures into production, or derive the acceptance hash from an unreviewed caller-supplied record. An authorized operator installs the real policy only after independently reviewing repository identity, exact source/build, deployment record and selected operation. Keep the completed policy and source-to-original evidence map outside the repository.

The shared repository group is `repository`, `repositoryId` and `repositoryPrivate`; controllers require the approved destination name, an actual assigned positive ID and public visibility. Runtime acceptance requires `deploymentRecordSha256`; profile detection also requires `sponsorAddress`. Controller artifact/source keys are documented by the operator source and ops guide, including both `acceptedExecutableSha256` and `acceptedExecutableSizeBytes` (positive, at most 10 MiB); acceptance retains exact byte length and hash. Missing fields for an unselected optional feature do not enable it; selecting the feature requires all its own fields and its separate trusted approval files.

| Expired draft archive | `authorizeAbandonPolicies`; ordered exact original policy allowlist with source/order/payment/payer/order-hash/consent-hash. Later dispositions require the first original. Fresh canonical expiry/non-effect proof remains necessary. |
| UNKNOWN authorization isolation | `authorizeIsolationPolicy`, `acceptedExecutableSha256`, `merchantAddress`; exact original source/order/payment/payer/signature/message/wire/journal/consent/busy/action hashes. The separately installed runtime policy additionally supplies the immutable `archiveSha256`. All original reservations remain. |
| Public merchant demo | `merchantDemoPolicy`; origin/network/program/sponsor/merchant/mint, fixed budget and order/relay ceilings; separately installed policy adds a nonempty `reference` and must exactly match. A payer message enables only fixed original-order actions. |
| Admission journals and migrations | `admissionContracts.orders` / `.relay-attempts`, each with the exact original `reference`, `initialMaximum` and ordered `migrations`. Each step supplies `step`, safe archive basename, exact reason, original cap/used/carry-forward and new cap. Runtime requires the selected kind and exact reference. The current cap must equal the initial cap or a configured transition; every preceding archive is mandatory. Foreign, future, partial, missing or inconsistent archives refuse. Used slots cannot decrease. An empty migration list is valid only for an independently reviewed genuinely unmigrated journal whose initial cap matches its original policy. |
| Explicit smoke / lab | `devOrigin` / `publicOrigin`; configured runtime origin and original-order consent/terms remain authoritative. |

Shape validation is insufficient: addresses/signatures and linked hashes must be valid, the network and live finalized executable must match, migration snapshots must preserve the original counters, and any selected feature retains its existing privileged filesystem and ownership checks. Neither the schema nor a completed policy grants live execution permission. Multi-UID UNKNOWN-CAPTURE recovery remains unsupported, and its CLI continues to refuse before keys/stores/RPC.

The reusable `AdmissionJournal` constructor requires an explicit `AdmissionContract`. Installed runtime entrypoints obtain it only through `loadAdmissionContract` from the fixed trusted policy. Embedders must supply the independently accepted original reference, initial cap and complete transition history; deriving these from mutable current state would erase the migration safety boundary. The library never initializes or reconstructs missing live journals automatically.

The stopped unknown-authorization isolation operator also requires `restaurantCustody: {uid, gid}` from the fixed trusted policy. Both identifiers must be positive bounded integers and match the actual private orders directory, including its exact 0700 mode. The operator pins that directory through proof and persistence, transfers the exclusive archive descriptor to the approved custody, seals it to 0400 and flushes it. A mismatch or interrupted write leaves a blocking unusable entry and grants no outcome repair or retry authority. Determine these values from the independently reviewed installation; never copy fixture IDs.
